## Implemented and exercised

### Single style

- `StyleProfile.swift` persists one trimmed value under `be-nice.style.guide`; there are no raw-sample, language, or audience keys in the new schema.
- `StyleExtraction.swift` requires exactly `{"guide":"..."}` and rejects markdown, extra/missing fields, blank output, overlong guides, and delimiter injection.
- Settings → Personal Style is connected to the same `ModelClient.complete` path as optimization. A remote endpoint is disclosed before extraction; samples are sent only after explicit Extract.
- Extract updates only the editor and refreshes the local/remote privacy disclosure from the current endpoint immediately before the shared extract action. Save validates a nonblank reviewed guide, persists it, and clears raw samples; blank or invalid saves preserve both the saved guide and samples. Close clears raw samples; stale extraction completions cannot permanently lock the window.
- A real ad-hoc debug `.app` completed deterministic loopback Extract → editable result → Save. Independent reads returned `Use warm, concise sentences and keep a friendly tone.` under `be-nice.style.guide`, the request log contained one system + one sample user message, and the sample editor was empty after Save.
- Rebuilding the ad-hoc app invalidated access to the earlier fixture-only Keychain item. The known placeholder was deleted and recreated by the current app; no real credential was replaced. This confirms the documented cdhash/ACL limitation rather than a model failure.

### Green dot and compact card

- The trigger dot uses `NSColor.systemGreen`. Its existing allow-list, focused-target refresh, and write-back revalidation remain in force.
- `TriggerController.Target` carries an AppKit `anchorRect` used only for presentation. `PreviewLayout` places the card below the field, flips above when space is insufficient, and clamps to the visible screen frame.
- The former centered, large two-column preview is now a 440×230 native rounded `NSPanel` with one suggestion view, status, and Apply/Undo/Dismiss controls.
- The actual AppKit card was launched and inspected by screenshot. AX actions exercised suggestion → Apply (`Applied and verified.`) → Undo (`Original restored and verified.`) → Dismiss. Apply and Undo hide themselves when no longer applicable; busy states still prohibit dismissal. A stale target result now exits loading with `The target text changed. Try again.`
- This was a UI-state harness, **not a new live AX write**. The 13 M1 write loops were run with the old preview layout and remain historical evidence; the new card has not been rerun across the M1 matrix. The rebuilt debug app reported Accessibility Revoked during these checks; the final rebuilt binary requires a fresh grant before any new live matrix run.

## Real DeepInfra checks

Authorization: the user explicitly allowed the DeepInfra key in `~/.hermes/.env` for testing. A temporary local harness read it without printing it; it was not saved into be-nice, UserDefaults, the repository, request logs, or test output. All prompts contained the synthetic fixtures below, sent to remote `https://api.deepinfra.com/v1/openai/chat/completions`.

Training fixtures included casual Chinese colleague feedback and a friendly English review message. Held-out texts were:

1. `我们可能需要把发布顺延一天，因为还有一个崩溃没有修复。`
2. `I need your changes before our 3 pm review, otherwise we cannot ship today.`

### Iteration 1 — `deepseek-ai/DeepSeek-V4-Flash-0731`

Extraction and all four held-out rewrites completed. The extracted guide included `offer flexible timing`. Personalized outputs added alternative-timing concessions and weakened modality/consequences. An independent agent received only randomized, unlabeled A/B pairs and chose generic in both cases. Examples of the defects were `可能` → `我们建议`, adding `遗留`, and turning `otherwise we cannot ship today` into a softer positive statement.

### Iteration 2 — semantic safeguards, same model

The extraction prompt was restricted to transferable language choices and the optimizer explicitly prohibited changes to facts, modality, conditions, deadlines, request strength, or added alternative timing. The Chinese output stayed faithful and the English output retained the shipping condition, but the extracted guide still included the sample-specific phrase `no rush`. This intermediate run was inspected but **not counted as a blind pass**.

### Iteration 3 — `deepseek-ai/DeepSeek-V4.1-Flash`

Extracted guide:

> Use a warm, friendly, and appreciative tone with casual address terms and light punctuation like tildes or dashes. Keep sentences short and conversational, often breaking feedback into small digestible points. Structure feedback by first acknowledging the work positively, then stating one or two specific, actionable tweaks, and closing with thanks or next steps. Prefer direct, concise phrasing over formal or elaborate language. When giving instructions, soften them with polite phrasing and avoid sounding demanding. Maintain a collaborative, low-pressure vibe, but still be clear about what needs to change.

Final held-out outputs:

| Case | Generic | Personalized |
|---|---|---|
| Chinese | 我们可能需要把发布顺延一天，因为还有一个崩溃问题尚未修复。 | 我们可能得把发布往后挪一天哈，因为还有个崩溃没修好~ |
| English | I need your changes before our 3 pm review; otherwise, we cannot ship today. | Thanks so much for your work on this~<br><br>Quick heads-up: I'll need your changes before our 3 pm review.<br><br>If we don't have them by then, we won't be able to ship today.<br><br>Appreciate you! |

A new independent agent again received only randomized, unlabeled pairs. It chose **generic in both cases**: Chinese personalized text tightened `可能需要` to `可能得` and added emotional markers; English personalized text added gratitude and social pressure and was unnecessarily long. No major factual distortion was found in this round, but semantic/pragmatic fidelity still took priority.

**M2 quality acceptance is therefore not met.** The single-style feature and real model path work, but the held-out personalized outputs did not beat generic rewriting under the blind rubric. Do not describe M2 as quality-validated. Preview-first review is a mitigation, not proof of output quality.
