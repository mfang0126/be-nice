## Runtime defects found and fixed

- Preview initialization activated an equal-width constraint before the two scroll views had a common ancestor. The resulting AppKit exception aborted the rest of `applicationDidFinishLaunching`, preventing Trigger startup, hotkey registration, and permission polling. The redundant constraint was removed; `fillEqually` remains.
- Preview columns initially rendered about 66 pt wide. Inner and outer vertical stack alignment now uses `.width`; minimum height was adjusted to avoid the identified minimum-size constraint conflict.
- Independent reviews also drove fixes for possible-write recovery, Apply-time range reselection/readback, cancellation/task-generation races, explicit confirmation before discarding available Undo, and Apply/Undo-busy close/trigger rejection. Final targeted re-reviews found no remaining high/medium issue in these changes.
- Rebuilding an ad-hoc app changes its cdhash. Accessibility had to be granted against the final binary, and the placeholder Keychain item had to be deleted/recreated by that same binary. A stale-item SecurityAgent prompt was denied; no password was entered and no real credential was read.

## Matrix-run anomalies and handling

- Chrome's managed window title contains the WebBridge tab-group suffix, so an initial exact-title driver check failed before fixture installation or product writing. Initial foreground/focus attempts also stopped before Apply. The final driver used LaunchServices activation and WebBridge focus; all three controls then passed.
- The first Safari input attempt observed an unexpected trailing `1` before Apply. Both the target and Preview's captured original contained `be-nice M0 fixture: hello world.1`; no Apply or Undo was executed. The source of that character is not established, so this attempt was rejected rather than counted as a pass or attributed to automatic model write-back. The unapplied Preview was closed, the dedicated fixture was restored under an exact-current-value guard, and a fresh input attempt plus textarea/contenteditable all passed.
- Safari's AppleEvent close timed out and left the fixture tab open. Cleanup subsequently verified the active fixture URL and exact tab title, then invoked only that tab's AX close action. The pre-existing Start Page tab was retained.

## Limits

This completes the M1 product-loop acceptance for the currently supported matrix targets, using fixed ASCII fixtures and the recorded app versions. It does not validate Unicode/IME, rich-text formatting, concurrent edits, full-screen/multiple displays, real third-party Electron apps, Slack, VS Code, or arbitrary apps. Terminal and insecure targets remain excluded. Product Undo is an AX write while the recovery flow is retained, not synthesized Cmd-Z. Closing or retriggering with available Undo requires explicit Discard confirmation. M2 style learning and M3 release hardening remain unfinished; this is not a public release.
